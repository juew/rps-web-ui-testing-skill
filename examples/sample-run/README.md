# Sample Run

This is a redacted example of how an evidence-based RPS Web UI testing run can be organized.

All names, IDs, task labels, table names, screenshots, and logs are fake or redacted. Do not treat this as real customer data.

## Scenario

- Product: `SampleRPS`
- Test chain: `SampleSourceDB -> SampleTargetDB`
- Case IDs: `sample_001`, `sample_002`, `sample_003`
- Goal: demonstrate how a controller agent links UI evidence, SQL/log evidence, report sections, scope rows, and defect decisions.

## Files

- `evidence-index.md`: sample evidence index.
- `report-flow.md`: sample Word report flow.
- `defect-register-flow.md`: sample defect-register flow.

## Privacy Boundary

The sample intentionally avoids real hosts, user names, customer names, secret values, connection strings, internal endpoints, and sensitive business data.
